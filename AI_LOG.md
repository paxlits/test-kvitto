Лог работы над тестовым: как я пользовался ИИ и что из этого вышло.

## Инструменты

- **OpenCode CLI** — терминальный ИИ-ассистент (модель Big pickle). Весь код проекта сгенерирован им, я правил и контролировал.

## Ключевые запросы

**1. Старт: собрать проект по ТЗ.**

> Собери API платежей на FastAPI по ТЗ: тарифы создаются при старте, все суммы в копейках целыми числами, промокод KVITTO10 (−10%, регистр не важен, неизвестный — 422), рассрочка 3/6/12 месяцев с графиком (сумма графика = сумме к оплате, остаток в первые платежи), статусы с допустимыми переходами, идемпотентность по Idempotency-Key (повтор — 200 с тем же платёжом), вебхук банка.

Сразу задал ограничения по стилю (это был второй посыл той же задачей):

> Продолжай, но есть замечания: 1. нужен асинхрон; 2. для сессий базы данных используй Annotated из typing; 3. в моделях используй Mapped и mapped_column вместо Column; 4. db.query() — устаревший API, SQLAlchemy 2.0 рекомендует select(); 5. идемпотентность не защищена от гонок; 6. добавь .env и .env.example для секретов.

**2. Финальная проверка.**

> Прогони pytest и покажи, что всё зелёное; сверь ответы API с ТЗ: копейки, рассрочка, повтор Idempotency-Key, запрещённый переход, 404.

## Где модель ошиблась и как я это заметил

1. **`pytest.ini` с секцией `[tool:pytest]`** — в pytest.ini такая секция не читается, из-за чего `asyncio_mode = auto` не включался и тесты вообще не запускались. Заметил по падению `pytest -v`. Исправил на `[pytest]`.
2. **Все запросы без слэша получали 307** — роуты были объявлены с `"/"` под префиксом `/payments`, реальный путь стал `/payments/`, а запросы шли без слэша. Заметил через curl: вместо 201 приходил 307. Исправил пути на `""`.
3. **Валидатор рассрочки пропускал дефект** — в Pydantic v2 `field_validator` не применяется к значению по умолчанию без `validate_default=True`, поэтому `method="installment"` без `installment_months` создавал платёж (201) вместо ошибки 422. Заметил прогоном теста. Добавил `validate_default=True`.
4. **Миграции были «бутафорией»** — папка `alembic/versions` пустая (а README звал `alembic upgrade head`), а сам `alembic.ini` сломанным форматом логирования (`KeyError: 'class'`). Заметил, когда запустил `alembic upgrade head`. Переписал `alembic.ini`, сделал асинхронный `env.py` и реальную миграцию.
5. **CI упал бы при первом пуше** — в `DATABASE_URL` не было `+asyncpg`, а `create_async_engine` с таким URL не создаётся. Плюс тесты переопределяли переменную через `setdefault`, и в CI они пошли бы на PostgreSQL с нерабочим URL. Заметил при просмотре `.github/workflows/ci.yml`. Исправил URL и сделал тесты безусловно на SQLite.
6. **Мёртвые файлы ради галочки** — `app/db/base_class.py` (бесполезный реэкспорт Base) и пустая папка `scripts/`. Выкинул.
